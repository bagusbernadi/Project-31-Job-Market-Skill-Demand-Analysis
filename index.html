Project 31: Job Market Scraping & Skill Demand Analysis

Tujuan project: membangun pipeline scraping mingguan yang mengumpulkan lowongan Data Analyst di Indonesia untuk menemukan skill, kota, industri, dan kisaran salary yang paling banyak diminta, sehingga prioritas belajar dan target lamaran bisa ditentukan berdasarkan data, bukan tebakan.

Kategori:Rancangan projectPasar kerjaData hasil scrapingPipeline + SQL + dashboard

Project Introduction

Bayangkan seorang pedagang yang ingin tahu barang apa yang paling dicari pembeli. Setiap minggu ia berkeliling pasar dan mencatat barang yang paling sering ditanyakan, harganya, dan di pasar mana barang itu laku. Setelah beberapa minggu, ia tahu barang mana yang sebaiknya ia stok lebih dulu.

Pencari kerja menghadapi hal yang sama. Ratusan lowongan Data Analyst muncul setiap minggu, masing-masing dengan daftar skill yang berbeda. Membaca semuanya satu per satu memakan waktu dan hasilnya sering hanya kesan, bukan angka.

Project ini meng-upgrade project scraping lama menjadi pipeline yang berjalan otomatis setiap minggu. Kode dan data 2.560 postingan dari project lama ditelusuri ulang (reverse engineering) untuk memahami cara kerjanya, lalu dibangun ulang dengan cleaning, database, analisis SQL, dan dashboard. Kata bergaris bawah putus-putus kuning bisa diklik untuk melihat artinya.

Gambaran alur kerja mencari skill yang dibutuhkan

Prosesnya bisa dibayangkan sebagai tiga jalur. Jalur pertama adalah cara pencari kerja membaca lowongan. Jalur kedua adalah masalah pada data lowongan mentah. Jalur ketiga adalah yang dibangun di project ini.

  1. Cara manual. Pencari kerja membuka Jobstreet, membaca puluhan lowongan, lalu menebak skill mana yang paling penting. Hasilnya bergantung pada lowongan yang kebetulan dibaca.
  2. Data mentah bermasalah. Lowongan yang sama bisa muncul berulang, salary ditulis dalam format bebas, dan nama jabatan serta lokasi ditulis berbeda-beda.
  3. Scraper mingguan. Program mengambil lowongan baru setiap minggu secara otomatis dengan jeda yang sopan, lalu menyimpan data mentah apa adanya.
  4. Cleaning, database, dan dashboard. Data dibersihkan, skill diambil dari job description, lalu disimpan di database dan ditampilkan di dashboard.

1. BackgroundKenapa tema ini dipilih

Latar belakang masalah

Saran tentang skill Data Analyst yang "paling dicari" biasanya berasal dari artikel umum atau pengalaman orang lain, bukan dari lowongan di Indonesia saat ini. Project scraping lama sudah mengumpulkan 2.560 postingan, tetapi hanya sekali jalan. Akibatnya:

  • Tidak ada gambaran perubahan dari minggu ke minggu, karena data hanya diambil satu kali.
  • Salary sulit dibandingkan karena ditulis dalam format bebas, misalnya "8–12 jt", "IDR 10.000.000", atau tidak dicantumkan sama sekali.
  • Nama jabatan dan lokasi tidak seragam, sehingga hitungan per kota atau per level bisa keliru.
  • Keputusan belajar skill berikutnya dan memilih kota target lamaran masih berdasarkan tebakan.

Alasan memilih tema ini sebagai portofolio

  • Data nyata yang relevan. Datanya berasal dari lowongan sungguhan, dan hasilnya langsung dipakai untuk rencana switch career ke Data Analyst.
  • Menunjukkan skill end-to-end. Scraping, cleaning teks yang berantakan, database, SQL lanjutan (CTE, window function), otomatisasi terjadwal, dan dashboard.
  • Tingkat kesulitan sulit. Analisisnya deskriptif, tetapi parsing salary, normalisasi teks, dan pipeline terjadwal menambah tantangan teknis.
  • Berdiri sendiri. Tidak bergantung pada project lain, dan memakai pola DuckDB + Streamlit yang sama dengan project portofolio lainnya.

5. ToolsAlat yang dipakai dan alasannya

Python (Playwright, requests, pandas)

Playwright membuka halaman lowongan seperti browser biasa, requests dipakai untuk halaman sederhana, dan pandas membersihkan data.

Kode lama ditelusuri dulu agar bagian yang masih berfungsi bisa dipakai ulang.

Regex + kamus skill

Mengambil skill dari job description dengan pola kata kunci dan daftar sinonim. Aturan sama untuk semua minggu.

Transparan dan mudah diperiksa. Tidak memakai LLM agar hasilnya konsisten dan gratis.

DuckDB + SQL

Database tempat semua tabel disimpan. SQL dipakai untuk analisis dengan CTE dan window function, misalnya perubahan skill share antar minggu.

Gratis, satu file, dan konsisten dengan project lain. Daftar portofolio menulis SQLite/PostgreSQL.

GitHub Actions

Menjalankan scraper otomatis setiap minggu dan menyimpan hasilnya, tanpa perlu menyalakan komputer.

Gratis untuk repositori publik dan mudah dipantau dari tab Actions.

Streamlit + Plotly

Dashboard interaktif: skill share, salary per skill dan kota, peta kota, tren mingguan, dan kalkulator skill match.

Semua tetap di Python. Daftar portofolio menyebut Looker Studio sebagai alternatif.

GitHub + Markdown

Menyimpan kode, kamus skill, tabel agregat, dan README berisi temuan dan rekomendasi.

Data mentah tidak di-commit, hanya agregat.

8. Success CriteriaKomponen tambahanKapan project dianggap selesai dan berhasil

Project dianggap berhasil jika

  • Kesembilan pertanyaan berlabel "Utama" terjawab dengan angka dari data.
  • Skill extraction mencapai precision dan recall minimal 90% pada 100 lowongan sampel berlabel manual.
  • Scraper mingguan berjalan minimal 4 minggu berturut-turut tanpa gagal, dan aturan situs dipatuhi.

  • Checklist standar terpenuhi: pertanyaan bisnis, data cleaning, analisis SQL, dashboard ter-deploy, README berisi insight dan rekomendasi.

9. Assumptions & LimitationsKomponen tambahanKeputusan yang sudah diambil dan hal yang perlu diwaspadai

Sumber data: reverse engineering project lama Sudah Anda setujui

Data 2.560 postingan dan cara pengambilannya ditelusuri ulang dari kode dan file di repo lama, lalu dilanjutkan dengan scraping mingguan. Periode dan situs sumber data lama ditulis setelah penelusuran selesai.

Tools: DuckDB + Streamlit + Plotly Sudah Anda setujui

Konsisten dengan project lain. Kolom Tools di daftar portofolio menulis SQLite/PostgreSQL dan Looker Studio / Streamlit, sehingga kolom itu sebaiknya diperbarui.

Ruang lingkup Usulan awal

Lowongan di Indonesia dengan judul mengandung "Data Analyst", "Business Intelligence Analyst", atau "Reporting Analyst". Satu platform (Jobstreet), ±12 minggu. Skill diambil dengan kamus kata kunci, tanpa LLM.

Hal yang perlu diwaspadai Usulan awal

Aturan situs. Scraping hanya dilakukan jika diizinkan robots.txt dan ketentuan situs. Data mentah tidak dipublikasikan.

Salary bias. Sebagian besar lowongan tidak mencantumkan salary. Angka salary hanya mewakili lowongan yang mencantumkannya, dan selalu ditampilkan bersama jumlah lowongan.

Satu platform. Jobstreet belum tentu mewakili seluruh pasar kerja. Lowongan di LinkedIn atau situs perusahaan tidak ikut terhitung.

Disebut belum tentu wajib. Skill yang tertulis di deskripsi bisa berupa syarat wajib atau sekadar nilai tambah. Kamus tidak membedakannya.
